# Устройства и сеансы

CMS владеет реестром входов, `web/SessionUser`, `components/UserSessions`,
моделью `CmsUserSession` и общим экраном профиля Admin/UPA. Они работают без
мобильного пакета, Firebase и таблиц подписок.

После применения `m261007_140000_user_sessions` включить
`components.user.trackSessions = true` для `SessionUser` в web-конфигурации.
Миграция создаёт только `cms_user_session`.
`userSessions.realm` должен быть стабильным идентификатором области входа.
Включение требует свежего входа: старые PHP-сеансы и remember-me cookies
не становятся автоматически зарегистрированными устройствами.

Выход отзывает отдельный секрет сеанса. Remember-me использует обычную
подписанную cookie Yii и дополнительную cookie сеанса; отозванный вход не
восстанавливается старой cookie. Реестр хранит только хеши секретов.
Сроки настраиваются в «Настройки → Компоненты → Skeeks CMS → Авторизация»:

- `auth_session_idle_days` — выход по бездействию, 0 отключает (по умолчанию 0);
- `auth_session_max_days` — максимальный срок входа, 1–365 дней (по умолчанию 365).

Политика едина для браузера и мобильного WebView. Берутся настройки default/site,
пользовательские переопределения не могут менять политику безопасности.
При новом входе сохраняются `idle_timeout` и `absolute_expires_at`; `expires_at`
содержит ближайший предел. Активный запрос продлевает период бездействия, но не
абсолютный предел. Push и фоновые задания его не продлевают. Проверка времени
происходит на следующем запросе/отправке, отдельный таймер выхода не требуется.
Изменение настроек применяется при следующем входе; восстановление по cookie
сохраняет прежнюю политику записи. Для немедленного действия отозвать сеансы.

Cms передаёт загруженные настройки в SessionUser после собственной инициализации:
обратное чтение Cms из User при восстановлении входа создаёт рекурсию bootstrap.
Длительность положительной remember-me cookie нормализуется к общему пределу;
нулевая длительность (не запоминать вход) сохраняется. Обе cookies продлеваются
совместно и не позволяют обойти срок записи. Раннее удаление cookies или данных
серверной сессии может потребовать входа раньше заданного срока.

Без Cms либо при `sessionLifetime = null` сохраняется прежний расчёт из
remember-me/PHP timeout. Программные ограничения `userSessions.maxLifetime` и
Yii `absoluteAuthTimeout` остаются дополнительными верхними пределами;
Yii `authTimeout` продолжает независимо ограничивать бездействие PHP-сеанса.
При выключенном trackSessions поведение обычного Yii User не меняется.
Принудительный выход вызывает события Yii beforeLogout/afterLogout; veto
beforeLogout не может сохранить доступ по отозванному секрету.

Очистка: `yii cms/user-sessions/cleanup 30 500` удаляет одну порцию до 500
записей текущего realm, отозванных или истёкших более 30 дней назад. Планировщик
вызывает команду регулярно; зависимость от cms-job не требуется. Связанные
мобильные записи удаляются по FK CASCADE. Не использовать реестр как бессрочный
журнал аудита; требуемый срок хранения задаётся отдельно от срока входа.

Расширения подписываются на два события `UserSessions`:

- `EVENT_REVOKED`: `UserSessionsRevokedEvent` с `sessionIds`, `userId`, `realm`.
  Событие вызывается внутри транзакции отзыва. Изменения слушателей на том же
  DB-соединении откатываются вместе с отзывом при ошибке. Внешние запросы
  здесь запрещены; ставьте задания в общую транзакционную очередь.
- `EVENT_RENDER_DETAILS`: `UserSessionDetailsEvent` с `session`, `view`, `html`.
  Расширение добавляет свой отрендеренный HTML в уже проверенную карточку
  сеанса. Его POST-действия самостоятельно проверяют текущего пользователя,
  принадлежность записи и CSRF.

Подписки push и мост Capacitor принадлежат отдельному `skeeks/cms-mobile`.
Ядро не импортирует его классы, не регистрирует компонент, маршруты или задания.

Проверка: `php tests/user-sessions.php <vendor/autoload.php>` — отдельная SQLite,
настоящий lifecycle Yii User, без настройки или загрузки мобильного пакета.
